# 01-部署手册：手动全链路（今晚核心）

> 前置：`00-环境搭建.md` 已全部完成（kind 集群 + registry + ingress-nginx + metrics-server 就绪）
> 目标：把三个业务服务 + 三个中间件 + SkyWalking 全量部署，浏览器打通下单链路

---

## 1. 把项目放到目标机器

```bash
# WSL2 终端（假设项目 zip 解压在 Windows 的 D:\k8s-demo）
cp -r /mnt/d/k8s-demo ~/k8s-demo && cd ~/k8s-demo
```

## 2. 装 JDK 17 + Maven（WSL2 内，构建发生在这里）

```bash
sudo apt update && sudo apt install -y openjdk-17-jdk-headless maven
java -version && mvn -version
```

## 3. 构建 + 打镜像 + 推送到本地仓库

```bash
cd ~/k8s-demo

# 3.1 先验证编译通过（首次拉依赖较慢，耐心等）
mvn -q -DskipTests package

# 3.2 打三个镜像（多阶段构建，Dockerfile 在 docker/ 目录）
docker build -f docker/Dockerfile.user    -t localhost:5000/k8s-demo/user-service:latest .
docker build -f docker/Dockerfile.order   -t localhost:5000/k8s-demo/order-service:latest .
docker build -f docker/Dockerfile.gateway -t localhost:5000/k8s-demo/gateway:latest

# 3.3 推送（kind 集群的 Pod 将从这里拉取）
docker push localhost:5000/k8s-demo/user-service:latest
docker push localhost:5000/k8s-demo/order-service:latest
docker push localhost:5000/k8s-demo/gateway:latest
```

## 4. 全量部署（按编号顺序 apply）

```bash
cd ~/k8s-demo
kubectl apply -f k8s/raw/
```

> YAML 文件名带编号，`kubectl apply -f` 一个目录会按文件名顺序应用：
> 00 命名空间 → 01 MySQL → 02 Redis → 03 RabbitMQ → 04~06 业务服务 → 07 Ingress → 08 HPA → 09 RBAC → 10 NetworkPolicy（不生效，见进阶手册）→ 11 SkyWalking → 12 Elasticsearch → 13 Kibana → 14 Filebeat（EFK 日志）

## 5. 观察启动过程（教学重点：学会看状态）

```bash
# 5.1 实时看 Pod 状态（Ctrl+C 退出）
kubectl -n k8s-demo get pods -w

# 5.2 等全部 Running 且 READY 列 = 期望副本数（约 3~8 分钟，首次拉镜像慢）
kubectl -n k8s-demo get pods
# 期望：user-service 2/2、order-service 2/2、gateway 2/2、
#       mysql-0 1/1、redis 1/1、rabbitmq 1/1、skywalking-oap/ui 1/1、
#       elasticsearch-0 1/1、kibana 1/1、filebeat 每节点各 1/1（共 3 个）

# 5.3 出问题时第一命令：describe 看 Events
kubectl -n k8s-demo describe pod <Pod名>
# 第二命令：看日志
kubectl -n k8s-demo logs -f <Pod名>
```

## 6. 配 hosts + 浏览器验证

**Windows 侧**（管理员记事本打开 `C:\Windows\System32\drivers\etc\hosts`，追加两行）：

```
127.0.0.1 k8sdemo.local
127.0.0.1 skywalking.local
127.0.0.1 kibana.local
```

浏览器/curl 验证（Windows 终端即可）：

```bash
# 查用户（gateway → user-service → MySQL）
curl http://k8sdemo.local/api/user/users/1

# 下单（gateway → order-service → Redis缓存/Feign调user → RabbitMQ）
curl -X POST http://k8sdemo.local/api/order/orders \
  -H "Content-Type: application/json" \
  -d '{"userId":1,"productName":"云原生实战手册","amount":99.9}'

# 查订单（读 Redis）
curl http://k8sdemo.local/api/order/orders/<上一步返回的id>

# SkyWalking 链路追踪界面
# 浏览器打开 http://skywalking.local
```

## 7. 验证三种通信方式（看日志找证据）

```bash
# 7.1 order-service 日志应出现：缓存未命中 → Feign 查询回填
kubectl -n k8s-demo logs -f deployment/order-service | grep 缓存

# 7.2 再下一单 → 应出现"缓存命中"（Redis 生效的证据）
curl -X POST http://k8sdemo.local/api/order/orders -H "Content-Type: application/json" -d '{"userId":1,"productName":"二次下单","amount":1.0}'

# 7.3 user-service 日志应出现"收到下单消息，用户积分 +10"（RabbitMQ 异步解耦的证据）
kubectl -n k8s-demo logs -f deployment/user-service | grep 收到下单

# 7.4 EFK 日志检索（日志集中采集验证）
# 浏览器打开 http://kibana.local → Stack Management → 索引模式（Index Patterns）
#   → 创建索引模式，填 k8s-demo-* → Discover 页面即可检索所有服务日志
# 点开一条日志，看 kubernetes.labels.app / kubernetes.namespace 字段
#   —— 这就是 Filebeat add_kubernetes_metadata 打的标，可按服务筛选
```

## 8. 滚动更新 + 回滚实验（今晚必练）

```bash
# 8.1 滚动更新：改副本数/镜像，观察 maxUnavailable=0 的效果
kubectl -n k8s-demo scale deployment order-service --replicas=4
kubectl -n k8s-demo rollout status deployment/order-service

# 8.2 模拟发布新版本（随便换个标签触发一次更新）
kubectl -n k8s-demo set image deployment/order-service \
  order-service=localhost:5000/k8s-demo/order-service:latest
kubectl -n k8s-demo rollout status deployment/order-service

# 8.3 回滚（发布出问题时救命命令）
kubectl -n k8s-demo rollout undo deployment/order-service

# 8.4 看历史版本
kubectl -n k8s-demo rollout history deployment/order-service
```

## 9. 优雅停机验证（可选但强烈建议）

```bash
# 开两个终端：
# 终端 A：持续下单
for i in $(seq 1 1000); do curl -s -o /dev/null -X POST http://k8sdemo.local/api/order/orders -H "Content-Type: application/json" -d '{"userId":1,"productName":"压测","amount":1}'; done
# 终端 B：中途删一个 Pod，观察流量是否全部成功（preStop + graceful shutdown 的效果）
kubectl -n k8s-demo delete pod <某个order-service的Pod名>
```

## 10. 清理与重建

```bash
# 只删应用不删数据（PVC 保留）
kubectl delete -f k8s/raw/
# 或连 PVC 一起清（数据全丢）
kubectl -n k8s-demo delete pvc --all
# 删集群重来
kind delete cluster
```

## 常见问题排查表

| 现象 | 排查命令/原因 |
|---|---|
| Pod 一直 Pending | `describe pod` 看 Events：多半是资源不足或 PVC 未绑定 |
| Pod CrashLoopBackOff | `logs <pod> --previous` 看上次退出日志；user-service 常见原因是 MySQL 未就绪（initContainer 已兜底）或配置错 |
| ImagePullBackOff | registry 不通：检查 3.3 是否 push 成功；`docker network connect kind kind-registry` 是否执行 |
| curl 404 | 路由路径错：gateway 是 `/api/user/users/1`（前缀 /api/user + StripPrefix=2） |
| curl 502/503 | 后端未就绪：`kubectl -n k8s-demo get endpoints` 看 Service 有没有后端 IP |
| 下单报 500 | `logs deployment/order-service`：可能是 RabbitMQ 未就绪（等 1 分钟自动重连）或 user-service 不可达 |
| SkyWalking UI 无数据 | 等 1~2 分钟；确认 OAP Pod Running；`logs skywalking-oap` |
| Kibana 无日志/无索引 | Filebeat 未采集：`logs -f daemonset/filebeat` 看报错；ES 未就绪：`get pods` 看 elasticsearch-0 |
| ES 起不来（内存不足/崩溃） | ES 堆固定 1G，32G 机器一般无压力；`describe pod elasticsearch-0` 看 Events |
