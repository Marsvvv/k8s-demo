# 00-环境搭建：从零装好 WSL2 + Docker + kind 集群

> 适用：一台全新的 Windows 机器（≥32G 内存，本项目的目标机器）
> 全程约 30~60 分钟（主要花在下载）。**每条命令在「Windows PowerShell」或「WSL2 终端」里复制粘贴执行，见每节的【在哪执行】标注。**

---

## 0. 前置检查（Windows PowerShell，管理员）

```powershell
# 1. 确认 BIOS 虚拟化已开（应返回 True）
(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled

# 2. 确认 Windows 版本（WSL2 要求 Win10 2004+ / Win11）
winver
```

## 1. 安装 WSL2 + Ubuntu（Windows PowerShell，管理员）

```powershell
wsl --install -d Ubuntu-24.04
```

- 若提示需要重启：重启后继续。
- 重启后首次打开 Ubuntu 会要求创建 Linux 用户名/密码（记住密码，后面 sudo 要用）。
- 验证：

```powershell
wsl -l -v
# 应看到 Ubuntu-24.04，VERSION 列为 2
```

> 坑：如果 VERSION 是 1，执行 `wsl --set-version Ubuntu-24.04 2`

## 2. 换国内 apt 源（WSL2 终端，Ubuntu 内）

```bash
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak
sudo sed -i 's/archive.ubuntu.com/mirrors.tuna.tsinghua.edu.cn/g; s/security.ubuntu.com/mirrors.tuna.tsinghua.edu.cn/g' /etc/apt/sources.list.d/ubuntu.sources
sudo apt update
```

## 3. 安装 Docker（WSL2 终端）

```bash
# 官方一键脚本（能直连就用这个）
curl -fsSL https://get.docker.com | sudo sh

# 国内网络失败时改用阿里云镜像脚本
curl -fsSL https://mirrors.aliyun.com/docker-ce/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
echo "deb [arch=amd64 signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://mirrors.aliyun.com/docker-ce/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update && sudo apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

**配置镜像加速（国内必做，否则拉镜像极慢）**：

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json > /dev/null <<'EOF'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com"
  ]
}
EOF

# 启动 docker（WSL2 没有 systemd 时手动起）
sudo service docker start
sudo usermod -aG docker $USER   # 免 sudo 用 docker
# 退出重进 WSL 终端生效
```

验证：

```bash
docker run --rm hello-world
# 能打印 "Hello from Docker!" 即成功
```

## 4. 安装 kubectl / kind / helm（WSL2 终端）

```bash
# kubectl
curl -LO "https://dl.k8s.io/release/v1.30.0/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl && rm kubectl

# kind
[ $(uname -m) = x86_64 ] && curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.23.0/kind-linux-amd64
chmod +x ./kind && sudo mv ./kind /usr/local/bin/kind

# helm
curl -fsSL -o get_helm.sh https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3
bash get_helm.sh && rm get_helm.sh
```

> 网络坑：dl.k8s.io / kind.sigs.k8s.io / raw.githubusercontent.com 偶发连不上。
> 解决：在 Windows 上用浏览器/迅雷把对应文件下载下来，放进 `\\wsl$\Ubuntu-24.04\home\<你的用户名>\` 再在 WSL 里 sudo mv 到 /usr/local/bin（kubectl/kind）或 bash 执行（get_helm.sh）。

验证：

```bash
kubectl version --client && kind version && helm version
```

## 5. 创建 kind 多节点集群 + 内建镜像仓库（WSL2 终端）

在项目根目录（先把 k8s-demo 项目拷过来，见 01 手册 §1）：

```bash
cd ~/k8s-demo

# 用官方脚本创建带 localhost:5000 registry 的集群
bash docs/kind/kind-with-registry.sh
```

> 若 GitHub raw 下载失败，手动创建：把下面的配置存成 `/tmp/kind-config.yaml`：

```yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
```

```bash
# 手动方式：先起 registry，再建集群
docker run -d --restart=always -p "5000:5000" --name registry registry:2
kind create cluster --config /tmp/kind-config.yaml
# 让集群内 Pod 能拉到 localhost:5000：把 registry 接入 kind 网络
docker network connect kind registry
```

验证：

```bash
kubectl get nodes
# 应看到 3 个节点 Ready
docker ps | grep registry
```

## 6. 安装 ingress-nginx（WSL2 终端）

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml
kubectl wait --namespace ingress-nginx --for=condition=ready pod -l app.kubernetes.io/component=controller --timeout=180s
```

> 网络失败替代：Windows 浏览器下载该 URL 保存为 `ingress-nginx.yaml` 放进项目目录，再 `kubectl apply -f ~/k8s-demo/ingress-nginx.yaml`

## 7. 安装 metrics-server（HPA 依赖，WSL2 终端）

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
# 国内镜像加速：下载该文件后把镜像替换为国内源再 apply：
#   sed -i 's#registry.k8s.io/metrics-server/metrics-server#registry.cn-hangzhou.aliyuncs.com/google_containers/metrics-server#g' components.yaml
kubectl wait --namespace kube-system --for=condition=ready pod -l k8s-app=metrics-server --timeout=180s
```

## 8. 环境验收清单

```bash
kubectl get nodes                          # 3 节点 Ready
kubectl get pods -n ingress-nginx          # controller Running
kubectl get pods -n kube-system | grep metrics-server   # Running
kubectl top nodes                          # 能显示 CPU/内存（metrics-server 正常）
docker ps                                  # registry、kind 容器都在
```

全部通过 → 环境就绪，进入 `01-部署手册.md`。

## 常见坑速查

| 现象 | 原因/解决 |
|---|---|
| `wsl --install` 报 0x800701bc | WSL 内核过旧：管理员 PowerShell 跑 `wsl --update` |
| WSL2 里 docker 启动报权限 | 执行 `sudo service docker start`；开机自启可加 `wsl.conf` 的 `[boot] command` |
| kind create 卡住/超时 | 镜像加速未生效；查 `docker pull kindest/node:v1.30.0` 是否顺畅 |
| 拉 raw.githubusercontent.com 失败 | 用浏览器下载文件拷入 WSL（见 §4 坑） |
| Windows 访问 k8sdemo.local 失败 | hosts 未配置（见 01 手册 §6），或 ingress-nginx 未就绪 |
| WSL2 重启后 docker/集群没了 | docker：`sudo service docker start`；kind 容器：`docker start $(docker ps -aq)` 后 `kind` 自动恢复 |
