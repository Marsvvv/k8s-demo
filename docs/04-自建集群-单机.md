# 04-自建集群-单机：RKE2 + Rancher 真机落地

> 前置：00~03 已完成（kind 上练熟了部署、CI/CD、Helm、监控）
> 适用：一台能上网的真机或云主机（Ubuntu Server 24.04，≥4C8G、硬盘 ≥40G；本手册按全新机器写）
> 目标：在真机上用 RKE2 装出单节点 K8s，装上 Rancher 图形管理面并纳管集群，部署第一个应用
> 总耗时：约 60~90 分钟（主要花在下载镜像）
> 执行位置：所有 shell 命令都在**真机**上执行（SSH 或云厂商控制台）；浏览器操作在你自己电脑上

本章三个主角，先讲清楚它们是谁：

### 0.1 RKE2 是什么——"装 K8s 的安装包"

K8s 官方只给你一堆零件（kubeadm），要自己组装、自己配网络、自己管证书。**RKE2 是 Rancher 公司打包好的"整车"**——一条命令装完，内置容器运行时（containerd）、内置网络插件（Canal）、默认全链路 TLS 加密，安全默认值开箱即用。

> 为什么选 RKE2 而不是 kubeadm：对学习者，安装从"半天"缩到"十分钟"；对生产，官方安全加固 + 升级、加节点有官方工具链（06 章就用上）。

装完之后它在你机器上是什么样：一个叫 `rke2-server` 的 systemd 服务，开机自启、持续运行。

### 0.2 Rancher 是什么——"管集群的图形界面"

K8s 原生只有命令行（kubectl），资源多了以后在终端里看 Pod 列表、看日志、加用户都很痛苦。**Rancher 是一个图形化管理平台**：在浏览器里看资源、部署应用、建用户分权限，而且可以同时纳管多套集群（自建的、云上的）。

两个必须刻进脑子的边界：

1. **Rancher 不是 K8s 本身**——集群的"大脑"（apiserver）还是 RKE2 装的那套；Rancher 只是遥控器，遥控器坏了电视照样演。§4 会专门验证这一点。
2. **Rancher 和 RKE2 是同一个公司的两个产品**，配合最好，但不是必须配套：kubeadm 装的集群也能被 Rancher 纳管。

### 0.3 "纳管"是什么意思

"纳管" = 把自己已有的集群**登记**到 Rancher 里。动作的本质：在集群里跑一个 `cattle-cluster-agent` 组件，它把集群状态上报给 Rancher，同时接收 Rancher 发来的操作指令。登记之后，同一个集群就有了两种操作方式：**kubectl 命令行**和 **Rancher 界面**，随时可以交替使用（§5 验证）。

### 0.4 单节点意味着什么

单机部署 = 控制面 + etcd + 数据面三种角色挤在一台机器上：

- 优点：简单、真实可用——小项目、边缘场景（比如工地现场的一台小服务器）就是单节点跑生产
- 缺点：**这台机器挂了集群就没了**（单点故障），没有冗余

先接受这个缺点，06 章再加两台机器扩展成 3 节点高可用。现在装的时候留好伏笔：§2 里会生成一个 `node-token`，那是以后其他节点加入集群的"钥匙"。

## 1. 真机准备

```bash
# 1.1 核对配置（≥4C8G、硬盘 ≥40G，不够的话 Rancher 会非常卡）
nproc && free -h && df -h /

# 1.2 关闭 swap（swap 会干扰 K8s 的内存管理，不关 kubelet 直接报错拒启）
sudo swapoff -a
sudo sed -i '/swap/s/^/#/' /etc/fstab   # 注释掉 fstab 里的 swap 行，重启也不复活

# 1.3 设置主机名（节点要有唯一名字，Rancher 界面和日志都靠它认机器）
sudo hostnamectl set-hostname k8s-node1
hostname   # 应输出 k8s-node1

# 1.4 时间同步（K8s 组件间通信用证书，节点时间漂移会报"证书无效"）
sudo timedatectl set-ntp true
timedatectl   # 看 System clock synchronized: yes

# 1.5 防火墙（教学环境直接关；生产按端口放行，清单见 06 章）
sudo ufw disable
```

## 2. 安装 RKE2（在线）

```bash
# 2.1 安装：官方脚本把二进制装到 /usr/local/bin，并注册 systemd 服务
curl -sfL https://get.rke2.io | sudo sh -

# 2.2 启动 server 服务（注意名字：server = 控制面+数据面；worker 角色叫 agent，06 章用）
sudo systemctl enable --now rke2-server

# 2.3 盯启动日志（首次要拉几百 MB 镜像，日志刷屏是正常的，Ctrl+C 退出）
sudo journalctl -u rke2-server -f
```

配置 kubectl 并验证：

```bash
# 2.4 RKE2 自带 kubectl，在 /var/lib/rancher/rke2/bin 下，加进 PATH（顺手写进 bashrc 免去每次设置）
echo 'export PATH=$PATH:/var/lib/rancher/rke2/bin' >> ~/.bashrc
source ~/.bashrc

# 2.5 kubeconfig 是"操作集群的钥匙"，拷到 kubectl 的默认位置
mkdir -p ~/.kube
sudo cp /etc/rancher/rke2/rke2.yaml ~/.kube/config
sudo chown $(id -u):$(id -g) ~/.kube/config

# 2.6 验证：应看到 1 个节点 Ready
kubectl get nodes -o wide
```

> **这段输出说明什么**：ROLES 列显示 `control-plane,etcd,master` 三个角色挤在一行——这就是"单节点"的直观含义，一台机器把集群的三种活儿全扛了。STATUS 是 Ready 说明 kubelet 正常向控制面报到。
> 顺手看一眼你的"扩群钥匙"（06 章要用的）：`sudo cat /var/lib/rancher/rke2/server/node-token`

## 3. 安装 Rancher 管理面

先讲一个概念：**Rancher 需要一个"网址"**。它按域名区分服务，正式环境应该用你自己的域名；教学没有域名，用 `sslip.io` 这个免费通配域名——把 `<服务器IP>.sslip.io` 这种名字直接解析回这个 IP，不用改 hosts、不用买域名。

```bash
# 3.1 加 Rancher 官方 Helm 仓库
helm repo add rancher-stable https://releases.rancher.com/server-charts/stable
helm repo update

# 3.2 安装（把 <服务器IP> 换成你的真机 IP）
#   hostname：访问 Rancher 用的网址
#   bootstrapPassword：首次登录密码（和项目里 Grafana 的口令一致，好记）
#   ingress.tls.source=rancher：用 Rancher 自签证书，浏览器会警告，教学可接受；正式证书 05 章讲
helm upgrade --install rancher rancher-stable/rancher \
  -n cattle-system --create-namespace \
  --set hostname=rancher.<服务器IP>.sslip.io \
  --set bootstrapPassword=k8s123456 \
  --set ingress.tls.source=rancher

# 3.3 等就绪（首次拉镜像 5~10 分钟；rancher 那个 Pod Running 即完成）
kubectl -n cattle-system get pods -w
```

现在按理说浏览器就能访问 Rancher 了，但会撞上自建 K8s 的第一个经典问题——**"Pending 之谜"**：

```bash
# 3.4 Rancher 自带的 nginx-ingress 用 LoadBalancer 方式暴露服务，
#     而 LoadBalancer 是"云厂商帮我分配公网入口"的意思，裸金属/真机没有云 → 永远 Pending
kubectl -n cattle-system get svc | grep ingress
# EXTERNAL-IP 列是 <pending> —— 这就是原因

# 3.5 教学解法：把这个服务的类型改成 NodePort（K8s 会自动分配一个 3xxxx 端口）
#     服务名以 3.4 里看到的为准（通常是 rancher-ingress-controller，版本差异时按实际换）
kubectl -n cattle-system patch svc rancher-ingress-controller -p '{"spec":{"type":"NodePort"}}'

# 3.6 再看一次：443:3xxxx/TCP 中的 3xxxx 就是 Rancher 的访问端口
kubectl -n cattle-system get svc rancher-ingress-controller
```

> **这个补丁在教什么**：裸金属没有云负载均衡器，LoadBalancer 类型的服务没人给它分配 IP。NodePort 是"把端口开在每台机器上"的土办法，能访问但生产不这么干——**正规解法（MetalLB）就是 05 章的开场**。这里故意先撞坑，后面才知道 MetalLB 到底在解决什么问题。

浏览器打开 `https://rancher.<服务器IP>.sslip.io:3xxxx`，浏览器警告证书不安全（自签证书，正常现象）→ 点"高级 → 继续前往"。账号 `admin`，密码 `k8s123456`。

## 4. 纳管本地集群（让 Rancher 认识这台机器上的集群）

Rancher 界面操作（版本间按钮位置略有差异，找不到就点左上角 ☰ 搜索）：

1. 左上角 ☰ → **集群管理** → **导入已有集群** → 选 **Generic**
2. 集群名称填 `k8s-self`，点创建
3. 页面给出三条命令，**复制第一条**（类似 `curl --insecure -sfL https://.../v3/import/xxx.yaml | kubectl apply -f -`），到真机上执行
4. 回界面等待状态从 Pending 变成 **Active**（约 1~2 分钟）

**这条命令干了什么**：它在你的集群里装了一个叫 `cattle-cluster-agent` 的 Deployment，负责"把你集群的状态报给 Rancher、把 Rancher 的操作转达给集群"。验证一下：

```bash
kubectl -n cattle-system get pods | grep cluster-agent   # Running
```

> **关键认知：Rancher 只是遥控器。** 验证方法——把 Rancher 停掉，集群照常工作：
> ```bash
> kubectl -n cattle-system scale deploy rancher --replicas=0   # "拔掉遥控器电池"
> kubectl get pods -A | head                                   # 集群一切正常，kubectl 照常用
> kubectl -n cattle-system scale deploy rancher --replicas=1   # 记得把电池装回去
> ```
> 生产意义：万一 Rancher 挂了，应用流量不受影响，只影响"用界面管理"这件事。

## 5. 部署第一个应用（界面 + 命令行对照）

**在 Rancher 界面创建**：

1. 左上角 ☰ → **集群管理** → 进入 `k8s-self` 集群
2. 左侧 **工作负载 → 部署 → 创建**
3. 名称 `nginx-demo`，镜像填 `nginx:alpine`，副本数 `2`，直接创建

**回到命令行，验证"界面和命令行是同一个东西"**：

```bash
kubectl get deploy,pods -n default
# 应看到 nginx-demo 及 2 个 Pod —— 界面上的点击，本质就是 K8s API 的一次调用

# 命令行改副本数，再回界面刷新，数字也变了（双向互通）
kubectl scale deploy nginx-demo --replicas=3

# 把应用暴露出来验证真的能访问（临时土办法，正式入口在 05 章 MetalLB）
kubectl expose deploy nginx-demo --type=NodePort --port=80
kubectl get svc nginx-demo   # 记下 80:3xxxx 的端口
```

浏览器打开 `http://<服务器IP>:3xxxx`，看到 nginx 欢迎页 → 应用真的跑在真机上了。

> 这一节的深层含义：**UI 和 kubectl 是同一个集群的两种遥控器**。学会 Rancher 后别丢掉命令行——排障时 `kubectl describe` 永远比翻界面快（心法见 03 手册 §8）。

## 常见坑速查

| 现象 | 原因/解决 |
|---|---|
| `curl https://get.rke2.io` 连不上 | 网络问题；要么换镜像/代理，要么走 08 章离线安装路线 |
| `kubectl get nodes` 报 connection refused | rke2-server 还在初始化：`systemctl status rke2-server` 看状态，等 §2.6 验证 Ready |
| Rancher 页面 404 | URL 没用 sslip.io 域名或没带 3xxxx 端口；端口以 §3.6 实际输出为准 |
| 浏览器告警"证书不安全" | 自签证书的正常现象，教学点继续；正式环境 05 章换 cert-manager |
| 拉 rancher 镜像极慢/卡住 | 国内网络；耐心等，或配 RKE2 镜像加速（/etc/rancher/rke2/registries.yaml 指向国内镜像源） |
| 界面上"导入集群"找不到 | Rancher 版本界面差异：点 ☰ 搜索"导入" |
| 服务器重启后"集群没了" | 没丢：rke2-server 是 systemd 自启，等 1~2 分钟 `kubectl get nodes` 恢复；Rancher 是 Pod，集群起来后自动拉起 |
| 导入命令执行报错 | 报证书错误是导入命令的 --insecure 没生效（命令复制完整）；报 DNS 错误则是真机解析不了 sslip.io（真机无外网 → 看 08 章） |
