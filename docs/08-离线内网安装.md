# 08-离线内网安装：把整个集群搬进"没有互联网"的机房

> 前置：04~07 在**能上网**的机器上完成过（先跑通在线流程，再学离线，否则出问题分不清是离线的问题还是操作的问题）
> 适用：政企内网机房、涉密环境、工地现场等**完全不能访问互联网**的场景
> 目标：用一台"快递员"联网机准备所有安装包，通过移动介质搬进内网，完成 RKE2 + Rancher + Harbor + 应用的整套离线部署
> 总耗时：约半天（大头是下载和拷贝）
> 角色：**联网机 A**（能上网，负责下载/构建）、**内网机 B**（目标服务器，无外网）、**移动介质**（U 盘/移动硬盘/内网摆渡机）

---

## 0. 概念先行：离线安装到底"缺"了什么

在线安装时，命令背后偷偷发生着这些事：脚本从 GitHub 下载二进制、apt 从软件源下载依赖、docker/containerd 从镜像仓库拉镜像、helm 从仓库拉 chart、Rancher 从网上拉它自己的 system chart……**离线环境把这些"网线"全剪断了**。

所以离线安装的本质一句话：**把所有本该从网上拉的东西，提前在联网机上下载好、打包好，通过移动介质搬运进去，让内网机器以为"网线还在"**。

整个"货物流"：

```
联网机 A（有外网）                      内网机 B（无外网）
┌─────────────────────┐   移动介质    ┌─────────────────────────┐
│ 下载 RKE2 二进制/镜像 │ ──────────► │ 安装 RKE2（airgap 模式） │
│ 下载 Rancher 镜像/包 │ ──────────► │ 装 Harbor（内含镜像）    │
│ 下载 Harbor 安装包   │ ──────────► │ 把 RKE2/Rancher 镜像导进 │
│ 下载 docker 离线包   │ ──────────► │   Harbor 充当"内网仓库"  │
│ 构建业务应用镜像      │ ──────────► │ 装 Rancher（本地 chart） │
└─────────────────────┘             └─────────────────────────┘
```

> 内网里的 Harbor 就是内网的"小互联网"：所有镜像都从它拉，机器就不再需要外网了。

**在线 vs 离线对照**（后面每节都是这张表的展开）：

| 环节 | 在线（04~07 章） | 离线（本章） |
|---|---|---|
| 装 RKE2 | 脚本联网下载二进制和镜像 | 下载好的 tar 包 + 镜像包直接安装 |
| 装 docker | apt 源安装 | 提前下载的 deb 包 |
| 装 Harbor | 离线安装包（本来就是离线设计） | 同左，包搬进去即可 |
| 装 Rancher | helm 从仓库拉 chart + 联网拉镜像 | 本地 chart 文件 + 镜像从内网 Harbor 拉 |
| 应用镜像 | 构建机推 Harbor | 构建机 save 成 tar → 搬进去 load → 推内网 Harbor |

## 1. 联网机 A：打包所有"货物"

```bash
# 1.1 准备目录 + 工具
mkdir -p ~/offline/rke2 ~/offline/docker ~/offline/rancher ~/offline/harbor && cd ~/offline
sudo apt install -y zstd curl wget   # zstd 用来解压 RKE2 的镜像包

# 1.2 RKE2 三件套：安装脚本 + 二进制包 + 镜像包
#    版本和你的在线环境保持一致；如链接失效，去 github.com/rancher/rke2/releases 找最新 v1.30.x 替换
curl -sfL https://get.rke2.io -o rke2/install.sh
wget -P rke2 https://github.com/rancher/rke2/releases/download/v1.30.7/rke2.linux-amd64.tar.gz
wget -P rke2 https://github.com/rancher/rke2/releases/download/v1.30.7/rke2-images.linux-amd64.tar.zst

# 1.3 docker 离线 deb（联网机先配好 docker 官方源，只下载不安装）
sudo apt update && sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt update
mkdir -p docker/debs && cd docker/debs
sudo apt-get install -y --download-only docker-ce docker-ce-cli containerd.io docker-compose-plugin
# 依赖包已在 /var/cache/apt/archives/ 下，全部拷过来：
sudo cp /var/cache/apt/archives/*.deb .
cd ~/offline

# 1.4 Harbor 离线安装包（它内含全部镜像，本来就是为离线设计的）
wget -P harbor https://github.com/goharbor/harbor/releases/download/v2.10.0/harbor-offline-installer-v2.10.0.tgz

# 1.5 Rancher 两件套：本地 chart + 全部镜像
#    官方提供镜像清单和搬运脚本，照做即可
wget -P rancher https://github.com/rancher/rancher/releases/download/v2.10.0/rancher-images.txt
wget -P rancher https://github.com/rancher/rancher/releases/download/v2.10.0/rancher-save-images.sh
wget -P rancher https://github.com/rancher/rancher/releases/download/v2.10.0/rancher-load-images.sh
chmod +x rancher/rancher-save-images.sh rancher/rancher-load-images.sh
helm pull rancher-stable/rancher --version 2.10.0 -d rancher/   # 需要先 helm repo add（04 章 §3.1）
cd rancher && ./rancher-save-images.sh -i rancher-images.txt     # 生成 rancher-images.tar.gz（较大，耐心等）
cd ~/offline

# 1.6 业务应用镜像（在联网机构建并导出——把 <服务器IP> 换成内网 Harbor 的地址）
cd ~/k8s-demo   # 没有就先 clone 下来构建（05 章 §5.1 同款操作）
docker build -f docker/Dockerfile.user    -t core.harbor.<内网IP>.sslip.io:8443/k8s-demo/user-service:latest .
docker build -f docker/Dockerfile.order   -t core.harbor.<内网IP>.sslip.io:8443/k8s-demo/order-service:latest .
docker build -f docker/Dockerfile.gateway -t core.harbor.<内网IP>.sslip.io:8443/k8s-demo/gateway:latest
docker save -o ~/offline/k8s-demo-images.tar \
  core.harbor.<内网IP>.sslip.io:8443/k8s-demo/user-service:latest \
  core.harbor.<内网IP>.sslip.io:8443/k8s-demo/order-service:latest \
  core.harbor.<内网IP>.sslip.io:8443/k8s-demo/gateway:latest

# 1.7 清点货物（对照下面的清单核对，缺一样内网就卡在哪一步）
du -sh ~/offline/* && ls -R ~/offline
```

> 货物清单核对表：`install.sh` + `rke2.linux-amd64.tar.gz` + `rke2-images.linux-amd64.tar.zst`（RKE2）、`*.deb`（docker）、`harbor-offline-installer.tgz`（Harbor）、`rancher-2.10.0.tgz` + `rancher-images.tar.gz`（Rancher）、`k8s-demo-images.tar`（应用）。**全部拷进移动介质**。

## 2. 内网机 B：装 Harbor（先有"内网仓库"，后面全靠它）

```bash
# 2.1 从移动介质拷入并装 docker（deb 离线安装）
cd ~/offline/docker/debs && sudo dpkg -i *.deb
sudo systemctl enable --now docker && sudo usermod -aG docker $USER   # 重新登录生效
# 内网 docker 不需要配置镜像加速（没有网可加速），但要让 docker 信任内网 Harbor 的自签证书（同 05 章 §3.3）

# 2.2 装 Harbor（安装包里已有全部镜像，不需要网络）
cd ~/offline/harbor && tar xzf harbor-offline-installer-v2.10.0.tgz && cd harbor
cp harbor.yml.tmpl harbor.yml
# 改 harbor.yml（同 05 章 §3.4）：
#   hostname: core.harbor.<内网IP>.sslip.io（内网也能用 sslip.io 吗？不能！见下方坑）
#   https 端口和证书路径（自签证书在联网机生成好一并拷入，或内网用 openssl 现生成）
#   harbor_admin_password: k8s123456
sudo ./install.sh && sudo docker ps | grep harbor

# 2.3 在 Harbor UI 建项目 k8s-demo（公开）—— 后续所有镜像都推这里
```

> **内网没有 DNS 怎么办（重要坑）**：sslip.io 依赖公网 DNS，内网解析不了。两个办法：
> 1. 内网机器 + 客户端都改 `/etc/hosts` / Windows hosts，把 `core.harbor.<内网IP>.sslip.io` 指到内网 IP——名字照用，解析走 hosts
> 2. 内网有 DNS 服务器的话，直接加一条 A 记录（正规做法）
> 本手册按办法 1 走：**每台内网机器和客户端都要配 hosts**，别漏了 containerd 所在的那台。

## 3. 内网机 B：装 RKE2（airgap 模式）

```bash
# 3.1 解压二进制 + 放好镜像包（install.sh 会在 airgap 模式下直接读镜像包，不联网拉）
cd ~/offline/rke2
sudo tar xzf rke2.linux-amd64.tar.gz -C /usr/local
sudo mkdir -p /var/lib/rancher/rke2/agent/images
sudo cp rke2-images.linux-amd64.tar.zst /var/lib/rancher/rke2/agent/images/

# 3.2 用下载好的脚本安装（INSTALL_RKE2_ARTIFACT_PATH 告诉它"镜像在本地，别联网"）
sudo INSTALL_RKE2_ARTIFACT_PATH=/var/lib/rancher/rke2/agent/images ./install.sh

# 3.3 启动 + 验证（和 04 章完全一样的后续操作）
sudo systemctl enable --now rke2-server
sudo journalctl -u rke2-server -f     # 这次不拉网，启动快很多
export PATH=$PATH:/var/lib/rancher/rke2/bin
sudo cp /etc/rancher/rke2/rke2.yaml ~/.kube/config && sudo chown $(id -u):$(id -g) ~/.kube/config
kubectl get nodes
```

> 输出解读：和在线安装的唯一区别是启动快、无网络日志。到这一步，内网已经有 K8s 了——但**所有应用镜像还拉不到**（Harbor 里还空着），下一步把镜像"灌"进 Harbor。

## 4. 给内网 Harbor"灌镜像"（离线最核心的一步）

```bash
# 4.1 先解压 RKE2 镜像包并 load 进 docker
sudo apt install -y zstd   # 若没装（离线 deb 或从联网机一起拷 zstd 的 deb）
zstd -d /var/lib/rancher/rke2/agent/images/rke2-images.linux-amd64.tar.zst -o ~/rke2-images.tar
docker load -i ~/rke2-images.tar

# 4.2 Rancher 镜像
cd ~/offline/rancher && docker load -i rancher-images.tar.gz

# 4.3 应用镜像
docker load -i ~/offline/k8s-demo-images.tar

# 4.4 批量推入 Harbor：把所有镜像重新打上"内网 Harbor"标签并推送
docker login core.harbor.<内网IP>.sslip.io:8443 -u admin -p k8s123456
#   对每个镜像执行：docker tag <原镜像> core.harbor.<内网IP>.sslip.io:8443/<原镜像路径> && docker push ...
#   镜像多，用脚本循环（存成 push-all.sh 执行）：
docker images --format '{{.Repository}}:{{.Tag}}' \
  | grep -v '^core.harbor' \
  | while read img; do
      new="core.harbor.<内网IP>.sslip.io:8443/$img"
      docker tag "$img" "$new" && docker push "$new" || echo "失败: $img"
    done

# 4.5 让 RKE2 的 containerd 以后都从 Harbor 拉（mirrors 段 = "docker.io 的镜像改从我的 Harbor 拉"）
sudo tee /etc/rancher/rke2/registries.yaml > /dev/null <<'EOF'
mirrors:
  docker.io:
    endpoint:
      - https://core.harbor.<内网IP>.sslip.io:8443
configs:
  "core.harbor.<内网IP>.sslip.io:8443":
    tls:
      insecure_skip_verify: true   # 教学简化：跳过证书校验；生产把 ca_file 指到自签 CA（05 章 §3.5）
    auth:
      username: admin
      password: k8s123456
EOF
sudo systemctl restart rke2-server && kubectl get nodes
```

> **这步在干什么**：mirrors 配置让 containerd 把所有对 `docker.io` 的拉取请求改道到你的 Harbor——K8s 组件、Rancher、以及将来任何"写 docker.io 开头"的镜像，都会自动从内网 Harbor 拉，**Pod 从此不再需要外网**。

## 5. 装 Rancher（本地 chart + 内网镜像）

```bash
# 5.1 用搬进来的本地 chart 安装（不联网拉 chart）
cd ~/offline/rancher
helm upgrade --install rancher ./rancher-2.10.0.tgz \
  -n cattle-system --create-namespace \
  --set hostname=rancher.<内网IP>.sslip.io \
  --set bootstrapPassword=k8s123456 \
  --set ingress.tls.source=rancher \
  --set rancherImage=core.harbor.<内网IP>.sslip.io:8443/rancher/rancher \
  --set systemDefaultRegistry=core.harbor.<内网IP>.sslip.io:8443 \
  --set useBundledSystemChart=true
# 说明：systemDefaultRegistry 让 chart 内部所有镜像自动加 Harbor 前缀；
#       useBundledSystemChart=true 让 Rancher 用它打包好的内置系统 chart，不联网下载

# 5.2 等就绪 + 入口处理（和 04/05 章一样：NodePort 或装 MetalLB）
kubectl -n cattle-system get pods -w

# 5.3 之后：纳管集群（04 §4）、部署 k8s-demo（helm --set image.registry=core.harbor.<内网IP>.sslip.io:8443/k8s-demo）
#   —— 全部和在线流程相同，因为"网线"已经由内网 Harbor 接上了
```

## 6. 在线/离线总对照表（复习用）

| 步骤 | 在线（04~07 章） | 离线（本章） |
|---|---|---|
| docker 安装 | `curl get.docker.com \| sh` | deb 包 `dpkg -i` |
| RKE2 安装 | install.sh 联网下载 | install.sh + 本地二进制包 + 本地镜像包 |
| Harbor | 下载安装包（离线设计） | 同左，拷贝即可 |
| Rancher chart | `helm repo add` 联网拉 | 本地 .tgz 文件 |
| Rancher 镜像 | containerd 联网拉 | 镜像预先灌入 Harbor + mirrors 改道 |
| 应用镜像 | 构建机 push Harbor | 构建机 save → 搬运 → load → push |
| DNS | sslip.io 公网解析 | hosts 文件或内网 DNS |
| 出问题的排查思路 | 先看网络通不通 | **先看镜像在不在 Harbor 里**（90% 的离线问题） |

> 最后提醒：离线环境的"维护成本"比在线高——升级、打补丁、加新组件都要重新走一遍"联网机打包 → 搬运 → 灌入"流程。真实项目里建议把 §1 的下载步骤写成脚本存档，每次升级照跑一遍，形成固定交付物（这也是政企项目里"离线安装包"交付物的由来）。

## 常见坑速查

| 现象 | 原因/解决 |
|---|---|
| `./install.sh` 报找不到 artifact | INSTALL_RKE2_ARTIFACT_PATH 路径没指对，或镜像包没放进该目录 |
| install.sh 尝试联网卡住 | 环境变量没带（3.2 的写法），或脚本版本过旧不支持 artifact 参数 |
| `zstd -d` 报命令不存在 | zstd 没装：从联网机 `apt download zstd` 把 deb 一起搬进来 |
| dpkg 装 docker 报依赖错 | deb 包没下全：联网机 `--download-only` 后必须把 /var/cache/apt/archives 里**全部** deb 拷走（不只是 docker 那几个） |
| Pod 拉镜像失败（内网） | 90% 是镜像没灌进 Harbor 或 registries.yaml 没生效：先 `docker images` 确认镜像在、再 `curl -k https://core.harbor...:8443/v2/_catalog` 确认 Harbor 里有、最后查 4.5 是否重启了 rke2-server |
| Rancher 装好但 system chart 拉取失败 | `useBundledSystemChart` 没设 true，或镜像没全部灌入（rancher-images.txt 的镜像一个都不能少） |
| 浏览器访问 rancher 域名打不开 | 内网无 DNS：客户端 hosts 没配（§2 的坑） |
| Harbor 端口 8443 连不通 | 内网防火墙拦截：内网机器也要放行端口（04 章 §1.5 的 ufw disable 同样要做） |
